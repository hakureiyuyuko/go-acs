# 面板多语言（i18n）

目前支持 **中文（默认）** 与 **English**，面板右上角一个按钮切换（图标旁边显示 `English` / `中文`）。

## 为什么要 i18n、怎么做

- **选择语言**：`?lang=xx`（点切换按钮时带上，并写进 cookie `acs_lang`，有效期一年）
  → cookie → `Accept-Language`（浏览器语言）→ 默认中文。
- **文案怎么取**：模板里写 `{{T "中文原文"}}`，Go 里写 `i18n.T(lang, "中文原文", args...)`，
  前端写 `t("中文原文")`（译文由服务端按当前语言注入到 `window.I18N`）。

**为什么用中文字面量当 key**（而不是 `overview.title` 这种键名）：

1. 模板替换可以脚本机械化完成，不用给几百句话现起名字，也不会出现「键名和内容对不上」；
2. 同一条文案在模板、JS、后端天然共用一条翻译；
3. 漏翻一眼可见 —— 英文页面里还出现中文就说明漏了，验收里有断言卡这条。

代价：**改中文文案 = 改 key**，必须同步 `internal/i18n/strings_en.go`，否则英文会静默回落成中文。
所以有一道测试防线（`TestAllTemplateTextsTranslated`）：它会扫一遍模板与 `app.js` 里用到的
每个 key，少一条就报错。

## 模板的多语言实现

`Register` 时给**每种语言各解析一套模板**（`tpls map[string]*template.Template`），
语言在解析期就绑进 `T` 这个 FuncMap 函数里。这样：

- 模板里写法干净（就是 `{{T "..."}}`），每次渲染不用再做一次查表；
- 渲染时按请求语言挑一套即可（`renderLang`）。

计数类的文案要**整句带参数**（`{{T "共 %d 台" .Total}}`），不要用「词片段拼句子」
（`{{T "共"}} {{.Total}} {{T "台"}}`）—— 后者英文语序会错（把设备数说成 clients）。
这是第一版踩到的坑，已经在验收截图里发现并改掉了。

## 怎么加一种语言

1. 在 `internal/i18n/i18n.go` 的 `Langs` / `LangNames` 里加代码（如 `ja`）与自称（`日本語`）；
2. 新建 `internal/i18n/strings_ja.go`，`init()` 里 `Register(map[string]string{...})`；
3. `Normalize` 里加上该语言的识别（`ja` / `ja-JP` 之类）；
4. 跑 `go test ./internal/i18n/ ./internal/web/`：缺的文案会被测试逐条列出来。

## 验收

- 单测：`internal/i18n`（语言协商、译文查找、缺译文回落中文）、`internal/web` 的
  `TestAllTemplateTextsTranslated`（不漏翻）、`TestEnglishPagesHaveNoChinese`（英文页面无中文残留）、
  `TestLanguageNegotiation`（`?lang=` / cookie / `Accept-Language` 优先级）、`TestLoginPageEnglish`。
- `verify-s1.sh` 第 37b 节：默认中文、`?lang=en` 英文、切语言写 cookie、带 cookie 保持英文、
  `?lang=zh` 切回中文、**英文页面里没有中文残留**。
- 另做了一次「中文零回归」比对：改动前后抓同一批页面（列表/详情/无线编辑/设置/接口），
  归一化掉新增的语言切换链接与 `window.I18N` 之后**逐字节一致**，只剩时间戳这类动态值。
  做这种几百处机械替换时，这道比对最值钱。

## 还没做完的部分（下一步）

模板与前端脚本里的文案已经全部双语。**后端拼出来的字符串还没走 i18n**，英文界面下这几处
仍是中文（都是「动作之后」才出现的，静态页面上看不到）：

- 表单提交后的提示语（`internal/web/settings.go`、`web.go` 里的 notice/err 文案）；
- 无线/FTTR/终端弹窗里由 Go 拼的分组名与提示（`clients.go`、`fttr.go`、`wifi.go`）；
- 任务类型与任务结果（`internal/cwmp` 生成、存库后由面板显示）—— 这类要按「显示时查译文」处理，
  库里存的仍是中文原文，属于历史数据可读的折中。
