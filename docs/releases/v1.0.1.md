# v1.0.1 —— 修掉发布包里的升级脚本

程序本身没有改动（二进制与 v1.0.0 完全一致），只修 `update.sh` 与两处脚本健壮性问题：

- **`update.sh` 找错下载地址**：它去 GitHub 的 API JSON 里抠 `browser_download_url` 时正则贪婪，
  会跨过资产对象匹配到最后一个资产的地址 —— 于是「下载 tar.gz」实际下到的是 190 字节的
  `SHA256SUMS`。**SHA256 校验闸拦住了它（哈希对不上直接拒装，不会装上坏东西），但升级完全走不通。**
  现在改成按 release 资产的固定 URL 形状直接拼地址，API 只用来问「最新 tag 是哪个」。
- 配置文件不存在时，读端口的 `grep` 返回码 2 会在 `set -e` / `pipefail` 下中断整个脚本；
  这类取值函数统一容错。
- 解包加 `--no-same-owner`（容器 / 用户命名空间里 tar 还原属主会失败）。
- **回滚时连 `VERSION` 一起回退**：否则数据目录记着新版本、跑的却是旧二进制。

打包与部署脚本的设计取舍、以及这些坑是怎么被抓到的，记在
[`docs/notes/deploy.md`](../notes/deploy.md)。

## 升级到这一版

已经装了 v1.0.0 的机器（`update.sh` 在那一版走不通）：下载 v1.0.1 的包，解压后用里面的脚本：

```bash
tar xzf acs-1.0.1-linux-amd64.tar.gz && cd acs-1.0.1-linux-amd64
sudo ./install.sh            # 原地升级，保留数据库与 /etc/default/acs
# 或者
sudo ./update.sh             # 从 GitHub 拉（这一版的下载逻辑已经修好）
```
