# v1.3.2 —— 光功率：中兴这类「光口挂在 Optical. 下」的设备也能采到了

v1.3.1 加了「重新采集光功率」之后，真机验证结果两极：

- **华为 B671-1E3W**：点了就有数 ✅
- **中兴 ZXHN F610GV9**：还是不对 ❌

查了库里的参数名才发现原因：**中兴把光口放在 `InternetGatewayDevice.Optical.` 这棵子树下**
（库里能看到 `InternetGatewayDevice.Optical.` 这个对象节点），而 v1.3.1 在 TR-098 下
**只枚举了 `InternetGatewayDevice.WANDevice.`**，整棵 `Optical.` 子树被跳过，自然一个读数都拿不到。

## 改了什么

- TR-098 设备现在枚举**两棵**子树：`InternetGatewayDevice.WANDevice.` **和** `InternetGatewayDevice.Optical.`；
  数据模型根未知时 TR-098 / TR-181 的四棵都试（`InternetGatewayDevice.WANDevice.`、
  `InternetGatewayDevice.Optical.`、`Device.Optical.`、`Device.WANDevice.`）。
  枚举的代价很小（光口子树就十几个参数），漏一棵的代价是整台设备没读数。
- `cpesim` 的 `-optical` 新增 `-optical-in`：
  - `wan`（默认）→ `WANDevice.1.WANPONInterfaceConfig.OpticalRxPower / OpticalTxPower`
  - `optical` → `Optical.Interface.1.RxPower / TxPower`（**中兴 ZXHN 这类布局**，数值特意设为不同值便于验证来源）

## 升级后要做什么

光功率是**一次性采集**，不是自动的：

1. `sudo ./update.sh` 升到 1.3.2
2. 设备详情页 →「光功率」→ 点**重新采集光功率**
3. 等设备下次 Inform（几十秒到几分钟），收光 / 发光就有数了

每台设备各点一次即可，采到之后会一直保留（除非手动再采）。

**没有数据库结构变化。**
