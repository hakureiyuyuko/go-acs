# v1.2.5 —— 安全更新：工具链升到 Go 1.27.4

**功能零变化**：只换了编译器版本，代码逻辑、界面、配置、数据库都没有改动。
升级就是换二进制，重启即可。

## 为什么发这一版

用 `govulncheck`（v1.9.0，漏洞库 2026-11-11）扫 v1.2.4 的构建环境
（Go **1.27.1**），报出 **14 项会影响项目代码的漏洞**，另有 1 项不可达。
**全部来自 Go 标准库**，第三方依赖 0 项 —— 所以不用改任何依赖，升工具链即可。

| 影响面 | 内容 | 修复版本 |
| --- | --- | --- |
| `net/http` + 内置 HTTP/2（10 项） | HTTP/1 请求走私（CONNECT 拒绝后、2xx CONNECT 后不同步）、Trailer 头导致内存耗尽、Range 头无长度限制、反复 initial window 更新耗 CPU、HTTP/2 流量控制重复退款、HPACK 编码器竞态导致崩溃、恶意 framing 头被接受、`MaxBytesReader` 头竞态导致崩溃 | 1.27.2（`MaxBytesReader` 要 **1.27.4**）|
| `html/template`（2 项） | 连续模板表达式不重置上下文追踪；`yield` 未被识别为 regexp 前置关键字（模板注入） | 1.27.2 |
| `crypto/x509` | 不信任被攻陷的中间证书 | **1.27.3** |
| `crypto/tls` | ECH 外层扩展引用校验 | 1.27.2 |
| `net/textproto` / `mime/multipart` | MIME 头解析绕过内存限制 | 1.27.2 |

另有 `os` 的 Windows junction 逃逸问题（1.27.2 修复），但这个符号本项目走不到，**不可达**。

### 对 ACS 来说最要紧的三处

1. **`html/template` 的模板注入**：面板把设备上报的字符串（型号、`SerialNumber`、
   `ProductClass`、参数值）直接喂进模板，一台被劫持的 CPE 就是不可信输入源；
2. **`net/http` 那一组**：CWMP 端口本来就对设备（甚至公网）开放，面板端口对局域网开放，
   请求走私 / 内存耗尽 / 崩溃这几条都是直接打这两个端口的；
3. **`crypto/x509`**：主动唤醒设备时会去连设备的 `ConnectionRequestURL`，
   证书链校验是这条路上的第一道闸。

## 改了什么

- 构建工具链：**Go 1.27.1 → 1.27.4**；
- `go.mod` 增加 `toolchain go1.27.4` —— 以后谁用旧版本 Go 构建，go 会自动拉 1.27.4，
  避免再编出带这批漏洞的二进制；
- `README.md` / `README-en.md` 的构建要求写成 `Go 1.27.4+`；
- 实现笔记新增「依赖漏洞扫描」一节（清单、影响面、复现方式）。

## 升级

```bash
tar xzf acs-1.2.5-linux-amd64.tar.gz && cd acs-1.2.5-linux-amd64
sudo ./install.sh     # 或 sudo ./update.sh
```

配置与数据库完全不动；从 v1.2.4 升级没有迁移。

> 如果你在用 v1.2.4 的发布包，**建议升级**：那批二进制是用 Go 1.27.1 编译的，
> 带着上面列的全部问题。
