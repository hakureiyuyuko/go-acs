# v1.2.4 —— 以太网口、主动唤醒派发器、概览随设备周期刷新、参数映射表

七件事 + 一份协作说明。**这次有数据库结构变化**：启动时自动建 `param_aliases` 表并
种入 10 条华为映射（幂等，不动现有数据），所以升级只需换二进制。

## 1. 以太网口：详情页新区块

真机（HN8145X6N / 两台 V271-20）都报了 4 个网口 × 32 个字段。

- **区块**显示 端口名 / 状态 / 协商速率 / 双工 / MAC / 收发流量 / 采集时间，
  表头写「共 N 个口，已连接 M 个」；**没有网口对象的设备整块不显示**（不摆空表）。
- **速率/双工给人话，原文放悬停**：`MaxBitRate=2500` → 「2.5 Gbps」，
  `X_HW_Speed=Auto_10` → 「自动协商（10 Mbps）」，`X_HW_DuplexMode=Auto_Full` → 「自动协商（全双工）」；
  数字优先、协商值兜底。流量按 1024 进制换算（`35376428045` → 「32.9 GB」）。
- **只取状态类字段**：枚举时用 include 白名单筛（含 `Stats.BytesSent/BytesReceived`，
  能看出哪个口在扛流量），不把一百多个计数器全拉回来。TR-181 的 `Device.Ethernet.Link.{i}`
  不算网口（它也有 Status/MACAddress，串台就会多几行）。
- **块的位置**：一开始放在「基本信息」前面，按反馈改成**「基本信息」下方、「FTTR 子设备」上方**
  —— 网口是设备本体的属性，贴着基本信息看更顺。

## 2. 概览数据改成随设备周期上报刷新

起因：设备 9 在 `22:56` 上报过，但「以太网口」的采集时间还停在 `22:49`、FTTR 也是旧的。
因为当时概览只有一条固定兜底间隔（`-auto-refresh-wifi`，默认 10 分钟），`22:56` 那次上报
只是没到点。期望的是「设备多久报一次，界面就多久新一次」。

现在 **无线概况 / 以太网口 / FTTR 子设备**三块共用 `overviewDue`：

- **设备自己的周期上报**（Inform 事件 `2 PERIODIC`）→ 顺手刷 —— 这就是「随周期更新」；
- **兜底**：距上次采集超过 `-auto-refresh-wifi`（默认 10 分钟）也刷一次，
  防止有些设备不报 `2 PERIODIC`（或上报的是我们主动唤醒开的会话）导致数据永远不动；
- 周期那条路径还要过新增的 **`-overview-refresh-min`**（`ACS_OVERVIEW_REFRESH_MIN`，默认 **30 秒**）
  下限，上报很密的设备不至于每个会话都枚举一遍（`0` = 不设下限）。

关键前提：Inform 处理里入队的任务会在**同一个会话**接着下发，所以顺手刷不会额外叫醒设备，
也不会和下面的派发器形成循环（设备自己上报时正好有任务在跑，且唤醒事件是
`6 CONNECTION REQUEST`，不是 `2 PERIODIC`）。实测设备 9 由每 12 分钟刷一次变成
`22:59:17 → 23:01:17`，与它 2 分钟的上报周期对齐。

## 3. 我们发起的动作一律主动唤醒设备

以前「入队任务 → 等设备下次 Inform」：真机上报周期可以长到几十分钟，界面上点一下要等很久，
看着像坏了。现在有一条统一的任务派发器（`internal/cwmp/dispatch.go`），每
`-task-wake-interval`（`ACS_TASK_WAKE_INTERVAL`，默认 **10 秒**，`0` = 关）扫一次，
对「还有 pending 任务」的设备**四条全过才发 Connection Request**：

1. **在线**（离线的交给离线巡检去探，别白叫）；
2. **没有任务正在 running** —— 设备就在会话里，后续任务会被接着下发，不用叫；
3. **不是刚上报完**（5 秒内）—— 留点时间让这次会话把任务取走；
4. **距上次唤醒超过冷却**（30 秒）—— 人工点、离线探测、派发三路共用这个冷却。

为什么做成派发器而不是在十几个入队点各调一次唤醒：靠「记得调用」早晚会漏。派发器只看
「谁还有任务排队」，天然覆盖所有路径。实测：周期 **300 秒**的模拟器排一条任务后
**几秒内**被执行。

## 4. FTTR 子设备也定期刷新

子设备（子光猫）子树以前**只在纳管那次能力探测时采一次**，于是界面上的「采集」永远停在
那一刻 —— 子光猫的在线状态 / 终端数 / 信号是几天前的数据却还挂在页面上，看着像实时的。
现在跟无线概况一个节奏刷（见第 2 节的触发规则），子机离线时界面会如实显示**离线**，
而不是纳管时的旧快照。

## 5. 厂商私有参数映射表放数据库

光功率 / 温度 / 电压 / 偏流这些参数**各家名字都不一样**，同一台设备上还有按光模块寄存器
（SFF-8472）编码的原始值（如 `RXPower=254` 其实是 −15.95 dBm）。把这些知识写死在代码里，
支持一台新光猫就得改代码发版。

现在放库里（迁移 #5 建表、#6 种数据）：`param_aliases`（field / vendor / match_contains /
match_suffix / decode / priority）。加机型只加数据：

```bash
acs alias ls                 # 列出全部映射
acs alias add ...            # 加一条
acs alias rm <id>            # 删一条
acs alias kinds              # 看有哪些字段与换算方式
```

- **详情页**「基本信息」多了 `光模块温度` / `光模块电压` / `光模块偏流`（此前只有收/发光）。
- **映射优先、启发式兜底**：映射命中的解码值还要过**物理区间闸**（收光 −40~+10 dBm、
  温度 −40~120 ℃、电压 0~10 V、偏流 0~200 mA），一条映射都没命中时才退回按叶子名认方向的
  启发式。没数据就显示 `-`，**不编数字**。
- 换算已与设备自己的页面逐项对上：`11008 → 43.0 ℃`、`32260 → 3.226 V`、`14500 → 29.0 mA`。
