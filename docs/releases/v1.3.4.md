# v1.3.4 —— 光功率读数取错值 & 统一两位小数

针对真机上「中兴 ZXHN F610GV9 显示 385 dBm / 16687 dBm」的问题。
根因不是采集不到，而是**采到了但选错了参数**。

## 1. 同一方向命中多个参数时，按语义选而不是「谁先来用谁」

一台猫上往往同时存在好几个带 `power` 的参数。以中兴 ZXHN F610GV9 为例，
`InternetGatewayDevice.Optical.Interface.1.` 底下同时有：

| 参数 | 值 | 是什么 |
| --- | --- | --- |
| `RxPower` | `-23.4` | **真正的收光功率** |
| `TxPower` | `2.1` | **真正的发光功率** |
| `RxPowerPercent` | `23` | 私有百分比 |
| `TxPowerPercent` | `385` | 私有百分比 ← 界面上显示的 385 |
| `TxPowerRaw` | `16687` | 原始 ADC 值 ← 界面上显示的 16687 |
| `PowerAlarmThreshold` | `-30` | 告警门限 |

旧实现是「遍历到第一个命中的就用它」，而**遍历顺序取决于数据库返回顺序**，
不是参数的物理含义 —— 于是同一台设备刷新几次可能显示不同的数。

现在给每个候选参数打一个「有多像标准光功率」的分（按名字判断，
不看值、不猜值）：

- 名字里有 `optical` / `pon` → +8
- 叶子名是 `RxPower` / `TxPower` / `OpticalRxPower` → +10
- 容器是 `WANPONInterfaceConfig` / `Optical.Interface` → +3
- 名字里含 `threshold` / `alarm` / `percent` / `raw` / `status` / `voltage` … → **−10**

分高的胜；同分取更新时间更晚的（重采过的读数才是新的）；都一样则保留先到的，
保证结果不会来回跳。

## 2. 物理上不可能是光功率的值直接丢弃

光模块收/发光功率真实范围大约 **−40 ~ +10 dBm**（再高要烧模块，再低根本收不到光）。
超出这个区间的值一律不当光功率显示 —— 宁可显示 `-`，也不显示 `385 dBm` 这种
一眼假但看起来像真实读数的数。这一条同时也兜住了「厂家私有编码」这类情况。

> 注意：这条过滤是**兜底**，主力仍是上面的打分。两者叠加后，
> 那台中兴现在显示 `-23.40 dBm / 2.10 dBm`。

## 3. 读数统一两位小数

设备回的原值什么样都有：`-14`、`-14.0`、`-14.580`、`"-14 dBm"`、空。
以前原样透传，所以同一列里有的显示一位、有的没小数，对不齐也看不出差别。

现在统一格式化成两位小数：`-14.00 dBm`、`-23.40 dBm`、`2.50 dBm`。
解析不出数字的（`N/A`、`--`）原样显示，**不会**当成 0 —— 那会看起来像一个真实读数。

## 4. 能查到读数是哪个参数来的

- 概览页「收光 / 发光」两列 hover 显示 `来源：<参数名>`
- 设备页「光功率」区块下面直接列出「读数来源：`InternetGatewayDevice.Optical.Interface.1.RxPower`」

各家参数名不统一，出问题时能直接看到读的是哪个参数，不用去翻库。

## 升级后

```bash
sudo ./update.sh          # 或 ACS_VERSION=v1.3.4 sudo ./update.sh
sudo systemctl restart acs
```

**没有数据库结构变化。** 存量设备不用重新采集：取值逻辑是读库时算的，
重启后概览页立刻按新口径显示（前提是之前已经采到过光功率；没采过的
点一次设备页「重新采集光功率」，或重新纳管让它自动采）。
