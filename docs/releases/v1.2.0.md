# v1.2.0 —— 登录页鉴权、自动刷新、中英双语，外加一套压测工具

这一版把面板打磨成「能给客户看」的样子：**独立登录页**（可退出）、**5 秒自动刷新**、
**中英双语**；同时把「大规模断电恢复」的压测脚本化，顺手量清了并发上限的瓶颈在哪。

## 面板鉴权：不再用 HTTP Basic

- `GET /login` 独立登录页；登录后下发**会话 cookie**（HttpOnly + SameSite=Lax，7 天自动续期）
- 顶栏加了**退出**按钮；未登录时页面 303 跳登录页、`/api/*` 回 401 JSON
- **改账号密码会让所有旧登录态立刻失效**（当前浏览器会补发新票，不会被自己踢出去）
- 登录失败有固定延迟与同来源锁定；成功/失败都写日志
- 忘了密码照旧救急：用 `ACS_WEB_AUTH=off` 起一次即可进来改

HTTP Basic 的三个硬伤（没法退出、改密码吊销不掉、密码随每个请求 Base64 发出）就此绕开。

## 5 秒自动刷新（全局开关）

设备列表与设备详情右上角各有一个开关，**两边共用一个状态**（存在浏览器里）。
开着的时候每 5 秒自动刷新，在线/离线、探测中、任务进度不用手点。
两个体贴处：正在输入时不刷、弹窗打开时不刷；分页位置与参数过滤词会跨刷新保留。

## 中英双语

右上角一键切换，选择记进 cookie；没选过就跟随浏览器语言，兜底中文。
**模板、前端脚本、以及后端拼出来的提示语/任务结果全部双语**，英文页面里不会有中文残留
（验收里有断言卡着）。加一种语言的步骤见 `docs/notes/i18n.md`。

## 压测工具（新增）

```bash
scripts/loadtest.sh                  # 阶梯 10/50/100/200/400 台，每档用全新的库
scripts/loadtest.sh -n 200 -e 4484   # 指定台数与每台参数规模
```

按真机华为 V271-20 的模板（TR-098、3 台 FTTR 子设备、`X_HW_APDevice` 子树 4484 个参数）
模拟**集体上电**。本机（4 核）实测结论：

- 会话并发本身不是瓶颈：200 台小参数设备 10 秒内全部完成；
- **瓶颈是写入吞吐**：约 1.6–1.8 万参数行/秒 ≈ **3.5–4 台 V271 规模设备/秒**，
  ACS 全程只用 ~1 个核（SQLite 单连接把所有 DB 操作串行化）；
- 100 台同时上电约 26 秒完成；200 台约 1 分钟、400 台约 2 分钟，期间数据**全量入库**，
  超出 CPE 30 秒超时的设备会在下次周期上报补完；
- **不要靠调大数据库连接池提速**：实测 4/8 连接快 2–3 倍，但出现 `SQLITE_BUSY` 并丢写入
  （参数只入库 44%/32%），所以 `SetMaxOpenConns(1)` 是正确性要求。

细节与复现方式见 `docs/notes/loadtest.md`。

## 升级

```bash
tar xzf acs-1.2.0-linux-amd64.tar.gz && cd acs-1.2.0-linux-amd64
sudo ./install.sh     # 原地升级，保留数据库与 /etc/default/acs
# 或者： sudo ./update.sh   # 从 GitHub 拉，带校验与失败回滚
```

- **没有数据库结构变化**，直接覆盖即可；升级后第一次打开面板会看到登录页（账号密码不变）。
- 面板若跑在公网上，建议仍然放在内网或用反向代理加 TLS。
