# v1.3.1 —— 收光 / 发光：补上采集，也不再只认固定参数名

v1.3.0 给概览页加了「收光 / 发光」两列，但**真机上全是 `-`**。两个原因，各修一处：

1. **光功率从来没被采集过**。纳管时下发的只有基本信息（`DeviceInfo.*` 那批），
   里面没有光功率；设备页也只有「重新采集无线概况」，没有对应入口。
2. **参数名认得太窄**。光功率在 TR-069 里**没有统一命名**，原实现是枚举
   `RxPower` / `X_HW_RxPower` / `OpticalPowerRx`… 这一类写法去比对，
   各家私有的命名（华为、中兴、烽火各不相同）基本都漏掉。

## 改了什么

- **设备页新增「重新采集光功率」**（`POST /devices/{id}/optical`，REST 同款 `/api/devices/{id}/optical`）：
  枚举光口所在的子树 —— TR-098 是 `InternetGatewayDevice.WANDevice.`，
  TR-181 是 `Device.Optical.` / `Device.WANDevice.`；枚举完**同一个会话里接着把值取回来**。
  **不猜具体参数名**，设备报什么名字就存什么名字。
- **辨认改成按语义**：叶子名（去掉下划线/横杠后）含 `power` 且有「光」的意味
  （`optical` / `pon`，或者 `rxpower` / `txpower` 这类常见写法），方向看
  `rx` / `receive`（收）与 `tx` / `transmit`（发）。
  无线的 `TransmitPower` **仍然不算**光发射功率。
- **库的查询放宽**：凡是参数名里带 `optical` 或 `power` 的都捞回来，
  是不是光功率由代码判定 —— 在 SQL 里枚举写法只会漏。
- **设备页新增「光功率」区块**：显示收光 / 发光，回退到子设备读数时标注来源；
  没采到时明说「点上面的按钮采集一次」，而不是假装设备没光口。
- 枚举时跳过 `PortMapping` / `AssociatedDevice` / `Host.` / `IPv6` 这些又大又无关的表，
  取值名单上限 400 条。
- `cpesim` 新增 `-optical`：让主机上报 `WANPONInterfaceConfig.OpticalRxPower / OpticalTxPower`
  （**故意用非常规命名**，用来验证界面不是靠枚举参数名认光功率的）。

## 怎么用

设备详情页 →「光功率」→ 点**重新采集光功率**，等设备下次 Inform（默认几十秒到几分钟）。
采到之后概览页的收光 / 发光就有数了。设备本身不报这个参数的，采完依然是 `-`
—— 这个不猜，设备说了算。

**没有数据库结构变化。**
