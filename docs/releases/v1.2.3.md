# v1.2.3 —— 收/发光功率、改完端口自己重启、纳管凭据自愈、无线概览去掉假行

四件事，都是真机用出来的。**没有数据库结构变化**（升级只换二进制，库和配置不动）。

## 1. 光功率：详情页两行 + 列表页两列

新接了一台 **PON 接入的 V271-20**（联通定制，V5R023C10S200），它在 TR-069 里**确实报**收/发光，
但位置和名字都很"私有"，所以这版的做法是**枚举位置 + 按语义辨认**，而不是猜参数名。

**实测踩到的三个坑**（都写进了 `docs/notes/implementation-notes.md`）：

| 情况 | 真机表现 |
| --- | --- |
| TR-098 里 PON 接口的常规位置 `WANPONInterfaceConfig.` | 整棵回 **9005 Invalid parameter name**，枚举不了 |
| 读数真正在哪 | `…WANDevice.1.X_GponInterafceConfig.RXPower / TXPower`（对象名确实是拼错的 `Interafce`） |
| 同一棵里的 `X_CU_…OpticalTransceiver.RXPower / TXPower` | 报的是**没换算的原始值**（`254` / `10000`），当 dBm 显示就是错的 |

所以采集侧枚举 `WANDevice.1.` 整棵（用叶子名后缀只留"像功率的"那几个，取值名单很小）+
`Optical.` 整棵；辨认侧（`web.hostOpticalFrom`）三道闸：① 排除无线路径
（`LANDevice.1.WiFi.X_HW_Txpower` 这类会被认成发光功率）② 值必须落在光模块讲得通的
**−40 ~ +10 dBm**（私有百分比、原始 ADC 值、语音 Tone 的 −100 全挡掉）③ 同方向多候选时优先
路径里有 `pon` / `optical` 的。FTTR 子光猫的功率**不算在主机头上**（它们在 FTTR 表格里按行显示）。

- **详情页**「基本信息」多了 `收光` / `发光` 两行；读不到就写 `-`（不编数字，也不隐藏这一行，
  免得「没做这个功能」和「设备没上报」分不清）。
- **设备列表页**多了「收光 / 发光」两列 —— **只在真有设备报过时才出现**，一台都不报就不摆空列。
  列表页本来就要为无线概况扫一次参数表（5 秒自刷一次），所以光功率是**并进同一条查询**的，
  没有新开第二条全表扫描。
- 采集时机：首次纳管 / `0 BOOTSTRAP` 自动采一次；详情页「重新获取」也会顺带采一次。

**遗留**：这台 V271 的 `TXPower` 自报 `0`。0 dBm 在合理区间内（GPON 通常在 +2~+3 dBm），
所以界面如实显示 `0 dBm`，但它也可能是固件"没测到就填 0"的占位值 —— 待第二台同型号对照
或用光功率计核对。

## 2. 改完监听地址可以点「立即重启服务」

以前设置页只能写一句「重启服务后生效」，剩下的让用户自己去命令行。
现在保存过监听地址后，提示里多一个「立即重启服务」按钮（二次确认），确认后服务自己换进程生效，
浏览器自动跳到新地址；**失败当场回滚**（新端口被占、地址写错都拦在动手之前），不会把人晾在命令行前。

实现上最关键的一点：**端口不是配置，是内核里那个 socket**。第一版"起新进程重新 bind"必然失败 ——
没变的 CWMP 端口还被老进程听着（`address already in use`）。现在是**句柄交接**：
老进程把要用的监听句柄经 `ExtraFiles` 递给新进程，新进程 `net.FileListener` 接管，
所以换进程时 **CWMP 端口零断点**，设备那头看不到抖动。systemd 托管时不能自己 spawn
（单元是 `Restart=always`，会两个进程抢端口），改成干净退出交给 systemd 拉起。

## 3. 新设备接入的 ConnectionRequest 凭据：自愈

复核结论：凭据一直是全自动的，而且是在 `0 BOOTSTRAP, 1 BOOT` 那次上报的**同一次会话**里写下去
（真机耗时 6 秒完成全套纳管）。用户名设备会回读、密码永远回空串 —— 任务结果里那句
「设置成功；1 个参数设备未回读，无法核对」是**成功**的固有描述，不是失败。

这版补了两处洞：

- **判"规范好没有"改看任务历史**（密码读不回来，看库里的值永远判成"没写"）：写成功且值就是当前
  这套才算数；失败隔 10 分钟重试、连败 3 次停手并 WARN；设备自报用户名跟我们配置的不一致
  （运营商改过）→ 不管历史如何都重写。
- 顺带修掉"每次重启都白写一遍"：真机复核重启后设备 2、9 各上报一次，**凭据下发 0 次**，唤醒照旧成功。

## 4. 无线概况里那行「5G ｜ - ｜ 开 ｜ -」是假的

现象：详情页多出一行 5G、射频「开」、其余全空，还带一个点开什么都没有的「修改」。

原因：华为 TR-098 设备挂了**两套**无线对象 —— SSID 一级的 `WLANConfiguration.{i}`
（真机实例号 **1 / 5**）和射频一级的 `WiFi.Radio.{i}`（实例号 **1 / 2**）。代码里为兼容 TR-181
把两者按实例号合并，于是 `WiFi.Radio.2` 凭空造出一个「实例 2」，只带开关与频段两个字段。

改法：射频 / 接入点对象**只能补充已有实例，不能自己造一行**；另外什么都不报的实例不显示。
真机 1 / 2 / 9 三台的详情页与概览页都回到了「每台 2 行」。
