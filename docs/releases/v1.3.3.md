# v1.3.3 —— 显示项、批量下发、光功率自动采集

三个问题一起修。前两个是真 bug，第三个是缺的默认行为。

## 1. 「显示项」勾多了也只显示状态

面板里每个列是一个同名勾选框（`name="cols"`），浏览器提交上来是
`?cols=status&cols=serial&cols=rx` —— **多个同名参数**。解析时只取了第一个
（`q.Get("cols")`），所以不管勾几个，页面都只按第一列渲染。

改成把所有 `cols` 值拼起来一起解析。现在勾几个就显示几个，cookie 也按列序存全。

## 2. 批量下发：勾了「启用」却什么都没发生

两处问题，第二处更危险：

**a. 布尔项被「值没变化」吃掉。** 勾了「启用无线 SSID」时下发值 `1`，
而设备上这个参数原值本来就是 `1`，于是被当作「值没变化，无需下发」跳过 ——
界面上就是「勾了、点了下发、什么都没发生」，看着完全像功能坏了。
现在**布尔项一律下发**（幂等写一次没有副作用），SSID / 信道这类仍然只在真变了才写。

**b. 只勾「改」不勾值 = 悄悄关掉无线。** 布尔项的「值」是独立勾选框，
原来 `batchFieldValue` 无条件返回 `"1"`/`"0"`：没勾值就返回 `"0"`，
等于「想启用却下发了关闭」。现在改成三态（勾值=开 / 只勾改=关 / 都不勾=不改），
并且提交前 JS 会拦一下：勾了「改」却没勾值就提示补上或取消，不让人凭手滑关掉无线。

## 3. 首次纳管时自动采集光功率

以前光功率要每台设备手动点一次「重新采集光功率」，否则概览页两列永远是 `-`。
现在**首次纳管 / BOOTSTRAP 时自动采一次**（跟自动采无线概况、WAN 概况同一处触发）。
光功率变化慢，不会每次 Inform 都采；要看新读数仍然可以点设备页的按钮。

## 升级后

`sudo ./update.sh` → 刷新面板即可。**没有数据库结构变化。**
