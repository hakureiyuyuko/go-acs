# v1.3.5 —— 光功率诊断页

v1.3.4 加上「值必须在光模块的物理范围内」这条过滤后，中兴那台从
`385 dBm / 16687 dBm` 变成了 `-`。**这不是回归，是那条过滤生效了** ——
那台设备报上来的值确实不在光功率该有的范围里。

但「显示 `-`」有两种完全不同的原因，界面上分不出来，排查就只能靠猜：

- **设备压根没报**光功率参数 → 该去查采集
- **报了，但值离谱**被我们弃用 → 该去查那台设备的私有参数

这一版就是把判定过程摊开，让这两种一眼能分开。

## 新增：设备页「光功率诊断」

设备页「光功率」区块下面多了一个折叠面板（**没读出光功率时默认展开**），
列出这台设备**所有**疑似光功率的参数，以及每一个为什么用 / 不用：

```
[跳过] InternetGatewayDevice.Optical.Interface.1.RxPower = 385
       — 值超出光模块的合理范围（-40~+10 dBm） — ÷100 ≈ 3.85 dBm
[跳过] InternetGatewayDevice.Optical.Interface.1.TxPower = 16687
       — 值超出光模块的合理范围（-40~+10 dBm） — −÷1000 ≈ -16.69 dBm
```

表格下面还有一份**纯文本版**，直接选中复制就能贴出去问人，不用从表格里抄。

判定原因一共四种，都是大白话：

| 判定 | 含义 |
| --- | --- |
| 值超出光模块的合理范围（-40~+10 dBm） | 物理上不可能是光功率读数 |
| 同一方向有更像光功率的参数 | 分值输给了另一个参数 |
| 同一方向有更新的读数 | 同分，但对手的读数更新 |
| 主机自己已上报，子设备的不参与 | 主机有值时子设备不参与 |

## 疑似私有单位的换算建议

有些厂家不直接报 dBm，而是报 `0.1 / 0.01 / 0.001 dBm` 的整数；
收光功率是负数，部分固件还把它当无符号数报。所以诊断里会**正负都试**：
只有换算后落进 `-30~+10 dBm` 才给建议，且**只给最可能的一个**，不罗列一堆。

例：`385` → `÷100 ≈ 3.85 dBm`；`16687` → `−÷1000 ≈ -16.69 dBm`。

> 这只是**建议，不会自动套用**。猜单位等于编数，界面上只给线索。

## 界面上区分「没报」和「报了不敢显示」

- 一个疑似参数都没有 → 提示「还没采集到光功率……点上面的按钮入队一次采集」
- 报了但值都不合理 → 提示「设备报过疑似光功率的参数，但值都不在光模块的合理范围内，所以没显示」+ 自动展开诊断

## 升级后

```bash
sudo ./update.sh          # 或 ACS_VERSION=v1.3.5 sudo ./update.sh
sudo systemctl restart acs
```

**没有数据库结构变化**，存量设备不用重新采集。

升级后打开那台中兴的设备页，把「光功率诊断」里的纯文本复制出来 ——
有了真实的参数名和值，就能针对性地加规则（是换算单位，还是名字符合某种私有写法），
不用再靠猜。
